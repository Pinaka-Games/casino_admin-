What you need before starting
  • 5 logins: an Admin, an Agent, a Sub-agent belonging to that Agent, a second unrelated Agent, and a Player.
  • Two browsers (or one normal + one incognito window) so you can be logged in as two people at once and watch notifications arrive live.
  • The Admin login needs the Notifications menu visible. If it's missing, ask an admin to tick Notification Inbox and Send Notification for your role under Access Control.
Two golden rules
  • Always refresh the page before reporting a problem. If the notification appears after refreshing, that's a different bug than it never arriving at all — and telling us which one saves a lot of time.
  • Notifications appear in two places — the bell icon at the top of every page, and the full Notifications → Inbox page. Check both.

1. Sending notifications

Log in as Admin. Go to Notifications → Send Notification.

1Send a message to one agent
  1. In your second browser, log in as the Agent and leave it open.
  2. As Admin, choose Send to one recipient, then Agent.
  3. Pick the agent from the dropdown. Type a title and message. Click Send notification.
Should happen You see a green success message. In the agent's browser, a popup appears straight away, the bell number goes up by 1, and the message is inside the bell — without them refreshing anything.
2Send a message to one sub-agent
  1. Same as test 1, but choose Sub-Agent instead of Agent.
  2. Log in as that sub-agent to check.
Should happen The sub-agent receives it exactly like the agent did. (Sub-agents connect differently behind the scenes, so this really does need testing separately.)
3An agent messages their own sub-agent
  1. Log out of Admin. Log in as the Agent.
  2. Go to Notifications → Send Notification and send a message to their own sub-agent.
  3. Check it arrived for the sub-agent.
Should happen Message arrives. In the sub-agent's inbox the sender is shown as Your Agent — not as Admin.
4Send an announcement to everyone
  1. As Admin, choose Broadcast to a group.
  2. Send one to All Agents. Note the number it says it sent to.
  3. Repeat for All Sub-Agents, then for Everyone.
  4. Log in as a couple of different agents and sub-agents to check.
Should happen Everyone in the chosen group gets the announcement, and each person gets it only once. The count shown matches roughly how many agents you have.
Watch for: anyone receiving the same announcement twice. That's a bug.

2. The inbox page

Log in as Admin. Go to Notifications → Inbox.

5Filter by who sent it
  1. Look at the four boxes at the top: Unread, From Users, From Agents, System. Note the numbers.
  2. Use the role dropdown and pick Users. Then Agents. Then Sub-Agents. Then System. Then back to All Roles.
Should happen Each choice shows only notifications from that kind of sender. The coloured label on each row matches what you filtered by.
6Filter by type, search, and unread
  1. Use the type dropdown — try Deposit, then Redeem, then back to All Types.
  2. Type a word from one of your test messages into the search box.
  3. Tick the Unread only box.
Should happen Each filter narrows the list correctly and jumps back to page 1. Search finds matches in the title, the message, and the sender's name.
Important: Unread only must show unread messages. If it shows ones you've already read, report it straight away.
7Mark as read, mark all, and delete
  1. Open the inbox in two browsers at once, logged in as the same admin.
  2. In the first browser, click Mark read on one row.
  3. Then click Mark all read at the top.
  4. Then click Delete on a row.
  5. After each step, look at the second browser without touching it.
Should happen The second browser updates by itself every time — the row fades, the bell number drops, "mark all" takes it to zero, and the deleted row disappears. The number never goes below zero.
8The bell dropdown
  1. As an agent with plenty of notifications, click the bell icon in the top bar.
  2. Scroll to the bottom and click Load more.
  3. Mark one as read and delete another from inside the dropdown.
  4. Close and reopen the bell.
Should happen Older messages are added below (no repeats, and it doesn't jump back to the top). Unread ones have a coloured stripe on the left. If there are none, it says "No notifications yet".

3. Notifications the system sends by itself

These appear in the Admin inbox automatically when things happen on the platform. Do the action, then check Notifications → Inbox as Admin.

9Deposits
  1. Create a manual deposit for a player → check the Admin inbox.
  2. Approve that deposit → check the Admin inbox again.
  3. Log in as that player and open their bell.
  4. Make a real card deposit (test/sandbox card) → check the Admin inbox.
Should happen Admin sees "Manual deposit pending review", then "Manual deposit approved", then "Deposit completed" for the card payment. The player separately sees "Deposit Approved" in their own bell.
Please also try: after a card deposit finishes, refresh the payment page or make the payment again from the same window. The admin should still only have one "Deposit completed" for that one payment — not two.
10Withdrawals (redeem requests)
  1. As a player, request a withdrawal.
  2. Check the Admin inbox.
  3. As Admin, reject it and type a reason in the notes.
  4. Log in as the player and check their bell and balance.
  5. Do it again with a different request, but approve it this time.
Should happen Admin gets a notification when the request comes in and again when it's decided. The player gets told it was declined, including the reason you typed, and their money is back in their balance. On approval they're told it was approved.
11Agent payout requests
  1. Log in as an Agent with commission available and request a payout.
  2. Check the Admin inbox.
  3. Now log in as a Sub-agent and request a payout.
  4. Check the parent Agent's inbox (not the Admin's).
Should happen Agent requests go to Admins. Sub-agent requests go to their own parent agent — because that's who approves them.
12ID verification (KYC)
  1. Take a player through ID verification until it is approved → check the player's bell.
  2. Take another player through until it is rejected → check their bell.
  3. As Admin, use Approve and then Revoke on a player's KYC → check their bell each time.
Should happen The player is told each time their verification status changes. Approval mentions they can now withdraw.
Watch for: the same result arriving twice, or a player who was already approved suddenly being told they're "under review" for no reason. Both are bugs.

4. Agent and sub-agent notifications

Do the action as Admin, then log in as the agent (and sub-agent) to check they were told.

13Changing commission rates
  1. Pick an agent who has sub-agents.
  2. As Admin, change that agent's commission rates.
  3. Check the agent's inbox, then each sub-agent's inbox.
Should happen The agent is told their rates changed, with the old and new numbers. Each sub-agent whose rate moved is told too, and it explains it happened because of their parent agent's change.
14Switching commission model (flat vs per-category)
  1. Switch an agent to FLAT, using a rate lower than one of their sub-agents currently has.
  2. Check the agent's and that sub-agent's inbox.
  3. Switch back to CATEGORY and check again.
Should happen Agent is told the model changed and what the flat rate is. Any sub-agent whose rate had to be reduced is told, with the old and new figures.
15Turning an agent on and off
  1. Deactivate an agent who has active sub-agents.
  2. Check the agent's inbox and each sub-agent's inbox.
  3. Reactivate them and check both again.
Should happen Agent and sub-agents are all told, both when switched off and when switched back on. The reactivation message correctly explains whether commission restarts for everyone or only for new players.
16Adding and removing sub-agents
  1. Create a new sub-agent under an agent.
  2. Check the parent agent's inbox, and log in as the new sub-agent to check theirs.
  3. Now delete that sub-agent.
  4. Check the parent agent's inbox.
Should happen Parent agent is told a sub-agent was added, and the new sub-agent gets a welcome message. On deletion, the parent is told — and the message names the person who was removed. If it shows a blank space or a long random ID instead of a name, report it.
17Paying and declining commission payouts
  1. Approve and complete an agent's payout → check that agent's inbox.
  2. Decline a different agent's payout, with a reason → check their inbox.
  3. As a parent agent, decline one of your sub-agent's payouts → check the sub-agent's inbox.
Should happen Completed payout: they're told the money has been paid. Declined: they're told it was declined, with your reason, and that the money is back in their balance. When declined by their parent agent, the sender shows as the agent — not Admin.

5. Player notifications

Check these in the player app bell, not the admin portal.

18Jackpot wins
  1. Trigger a game jackpot win for a player.
  2. Check their bell and their wallet balance.
  3. Now trigger a tier jackpot win (Grand / Major / Minor / Mini).
  4. Check their bell and balance again.
Should happen The winner is told they won, which jackpot it was, and how much — and the amount matches what landed in their wallet. Both kinds of jackpot must notify; they are two separate things.
This never worked before — players were paid and told nothing. It's the most important test in this section.
19Failed withdrawal payment
  1. Cause a payout to fail (for example, enter invalid payout details).
  2. Check the player's bell.
  3. Check the Admin inbox.
  4. Read the player's message carefully and compare it to what actually happened to their money.
Should happen Player is told the payout failed and that support has been notified. Admin is told too, including which provider failed and why.
Read the wording: the message must not promise the player an automatic refund, because no automatic refund happens here. If it says the money has been returned, report it.
20Announcements reach offline players
  1. Have player A logged in, and player B logged out completely.
  2. As Admin, create a new active message template / announcement.
  3. Player A should see it pop up straight away.
  4. Now log player B in and open their bell.
  5. Go back and edit and save the same announcement (change a word).
  6. Switch it off, then on again.
Should happen Player B sees the announcement in their bell even though they were offline when it was sent — this used to be lost forever. Editing an announcement that's already live does not resend it to everyone. Switching it off and back on does send it.

6. Connection and access

21Losing and regaining internet

Easy to skip, but this was a real problem — please do it.

  1. Log in as Admin and stay on any page.
  2. Turn off your wifi (or unplug the network). Wait about 30 seconds.
  3. While still offline, use another computer or phone to make a player submit a withdrawal request.
  4. Turn wifi back on. Wait a few seconds.
  5. Do not refresh the page. Just watch the bell.
Should happen The bell number updates on its own shortly after the internet comes back. Previously it stayed stuck, so new withdrawal requests sat there unnoticed.
22Notifications wait for you while logged out
  1. Log an agent out completely.
  2. As Admin, send them 2–3 notifications.
  3. Log the agent back in.
Should happen All of them are waiting in the bell with the right unread count. Nothing is lost by being logged out.
23Menu hidden without permission
  1. Ask an admin to create a role with the Notification Inbox and Send Notification permissions unticked, and give it to a test staff login.
  2. Log in as that person.
  3. Then have the permissions ticked on, and log in again.
Should happen Without the permissions, the Notifications menu is not visible at all. With them, it appears.
24Agents can only message their own sub-agents
  1. Log in as Agent A and open the Send Notification page.
  2. Open the recipient dropdown and look at the full list.
Should happen Agent A only sees their own sub-agents. They must not be able to pick another agent, or a sub-agent belonging to a different agent.
If you can see or select someone outside your own team here, report it as a security issue, not a normal bug.

7. Not bugs — please don't raise these

  • There's no way to turn notifications off or choose which ones you get. Not built yet.
  • Notifications are in-app only — no emails, no text messages, no phone push notifications for these events.
  • A small withdrawal and a very large one look the same in the inbox. No urgent/high-priority styling yet.
  • Notifications you've already read are automatically deleted after 90 days. Unread ones are kept.
  • Some things still don't notify anyone yet: failed deposits, password changes, new-device logins, weekly commission statements, and commission change requests. All planned, not missing by accident.
  • Messages typed by an admin by hand are always shown exactly as typed — they aren't translated.

8. Ask a developer to check these

These can't be tested by clicking around. Pass them to a developer.

  • Staff with no permissions can't send to everyone — a staff account with an empty role must be blocked from the send and broadcast functions, not just have the menu hidden.
  • One agent can't read or delete another agent's notifications by using someone else's notification ID.
  • Spanish translations for agent notifications work and fall back to English safely.
  • Sorting and filtering options can't be abused to reach data or cause errors.
  • Sending an announcement to thousands of agents completes quickly and doesn't time out.

When something fails

Please include:
  • The test number from this page.
  • Which login you used (Admin / Agent / Sub-agent / Player).
  • What you expected, and what actually happened.
  • Whether it appeared after you refreshed the page — this one detail matters a lot.
  • Roughly what time it happened, so the logs can be checked.
  • A screenshot if you can.
Keep this page updated whenever notifications change.
